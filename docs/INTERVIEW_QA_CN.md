# 面试问答准备

本文主要针对第一版受控工作流。第二版工具循环的讲法见 [AGENT_V2_DEMO_CN.md](AGENT_V2_DEMO_CN.md)。2026-10-04 全量验证记录为 116 个测试实例（第一版 84、第二版 32），含参数化实例；固定业务评测仍是 20 个虚构案例，不能把测试实例数量当作真实业务样本数量。

## 1. 这不就是接了一个大模型 API 吗？

如果只是 API wrapper，输入一段文字、返回一段文字就结束了。这个项目还处理了数据导入和去重、确定性硬过滤、透明评分、知识检索、结构化输出校验、一次重试、人工审批、状态持久化、运行日志、成本估算和固定评测。模型是一个组件，不是整个系统；这些能力仍有复查发现的缺陷，不等于全部已可靠。

## 2. 为什么不做多 Agent？

当前流程是线性的，而且每一步的责任非常清楚。拆成多个自主 Agent 会增加协调 Prompt、Token 消耗、状态同步和失败定位难度，却没有证明能提升结果。现在用普通函数和数据库状态就能完整交付。只有当不同任务需要独立工具权限、并行长任务或不同优化目标时，我才会考虑拆分 Agent。

## 3. 为什么用 FTS5，不用向量数据库？

知识库只有六份短文档，关键词也很明确。FTS5 零额外服务、可离线运行、成本为零，还能返回来源。向量数据库在大量多语言、语义表达差异很大的文档上更有价值；当前使用会增加部署和维护负担。生产数据扩大后可以做关键词与向量混合检索，并用评测决定是否值得。

## 4. 如何减少幻觉？

首先，不把预算、平台、粉丝范围交给模型。其次，最多检索三条资料并校验返回来源属于本次资料。Pydantic 拒绝缺字段、越界分数或额外字段，但只保证格式，不证明事实；来源成员校验也不证明资料支持结论。仍要人工复核，并用同时检查误报和漏报的评测检查判断质量。

## 5. 如果模型超时、返回无效 JSON 或服务不可用怎么办？

HTTP、解析、schema 与空 choices 等异常响应会受控处理并重试一次，最终失败不写成成功审核。新异常摘要只记录类型、HTTP 状态与尝试次数，不保留返回内容或凭证。演示可以切回 mock，生产使用再按实际需要增加后台任务与针对性的失败恢复。

## 6. 为什么只重试一次？

演示项目要控制等待时间和费用。无效结构连续出现时，盲目重试通常不会解决 Prompt 或服务问题。一次重试能覆盖短暂网络错误，同时保持行为可预测。生产环境会针对 429、5xx、超时和验证错误使用不同策略，而不是统一重复请求。

## 7. 成本怎么测？

每次响应中的输入和输出用量独立累计，乘以配置单价；验证失败与重试也计入，未知用量标记 `usage_unknown`。单价在 `app/config.py`，不直接读取价格环境变量。示例全量解释是 20 次请求，加草稿与审核是 22 次；完整20案例评测现在是25次，不含重试。日志估算仍需与账单核对，旧记录不会自动补齐。

## 8. 20 个案例能证明准确吗？

不能。旧 Top-5 和召回指标曾让退化响应获得满分，本轮已改为 Top-1、精确率与标签完全一致率，并对齐生产检索链路。退化响应现在得不到全部满分，但20个虚构案例仍只是小型回归集；真实质量需要授权、脱敏的人工标注案例和实际用户反馈。

## 9. Mock 的意义是什么？会不会太假？

Mock 的目标不是模拟模型智力，而是提供可重复的产品流程。它让没有账号、网络或余额时仍能开发 UI、数据库、审批和日志，也让自动测试不依赖外部服务。真实模型效果必须单独跑同一评测集，不能把 mock 分数当作线上效果。

## 10. 为什么不让模型直接决定创作者？

模型适合生成解释和发现软性关联，但报价、市场和数据质量是必须遵守的边界。最终合作还涉及品牌风险和商业判断，所以系统只提供候选排序，项目负责人做选择。这样既利用模型能力，也保留责任归属。

## 11. 如何保证不会误发邮件？

演示版完全没有邮件发送集成。生成后状态是 `pending`，人工批准才变成 `approved`。生产版接邮件系统时，会把批准记录、收件人预览、幂等键和发送审计放在调用前，默认仍不允许模型直接触发发送。

## 12. 为什么选择 FastAPI、SQLite 和原生前端？

这是一个单人面试演示，需要快速启动、容易阅读和低部署成本。FastAPI 对请求验证和 API 开发很直接，SQLite 同时提供关系数据和 FTS5，原生 HTML 表单在禁用 JavaScript 时仍能完成核心流程。生产规模出现并发、权限和团队协作需求后，再切换 Postgres、任务队列和组件化前端。

## 13. 你用 AI coding tools 写了很多代码，如何保证正确？

我先写清楚业务状态和不做什么，再按功能写失败测试。每一批实现后运行聚焦测试和完整测试；对 CSV 去重、硬过滤、结构化模型返回、人工审批、内容风险和六个页面都有自动检查。最后还用固定数据走完整工作流。AI coding tool 提高实现速度，但验收条件、边界选择和验证证据由我负责。

## 14. 当前最大的技术债是什么？

2026-10-03 已修复旧状态、AI 重排、评测盲点、重试用量和来源成员校验，当时第一版为 66 项自动测试；2026-10-04 又修正输入溢出、异常用量和启动配置优先级，第一版增至 84 个测试实例，全项目合计 116 个。详见 [复查记录](RECHECK_2026-10-04_CN.md)。剩余边界是：20 个虚构案例的评测还没证明真实模型质量；来源内容是否支持结论没自动证明；mock 政策固定，视频/链接未读取，总预算和币种未管理；没有认证、组织隔离与审批人，旧审核也不会自动重跑。项目仍不是生产就绪系统。

## 15. 如果给你两周把它用于真实团队，你先做什么？

第一阶段确认真实流程、字段和授权边界，用脱敏历史项目建立评测基线。第二阶段加入登录、角色权限、Postgres、迁移、后台任务、幂等和审计。第三阶段接一个最有价值的数据源与一个邮件沙箱，在人工审批下试运行。最后根据失败数据调整规则、Prompt 和知识检索，而不是先堆更多 Agent。

## 16. DeepSeek 的接入门槛高吗？

技术门槛不高：创建账号和 Key，设置环境变量，然后调用 OpenAI 风格的 Chat Completions。真正需要注意的是输出校验、超时、余额、价格变化、敏感数据、重试和评测。本项目已经把这些基础边界放在统一客户端里，所以切换模式不需要改业务页面。

## 17. 如果面试官问“你本人具体贡献了什么”？

可以如实回答：

> 这个项目使用 AI coding tools 协助开发。我需要能解释业务流程、模型接入、规则与审批，以及验证方法；我正在通过读代码和实际练习补足这些理解。介绍个人贡献时，我只说明自己真实参与的需求选择、测试、修改和复查，不把工具完成的步骤全部说成独立完成。

完成练习后，再按真实参与情况具体描述贡献。不要说自己训练了模型，也不要把当前 mock 的 100% 结果描述成有效的质量证明。
