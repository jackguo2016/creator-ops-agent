# 第二版创作者调研 Agent：演示与面试

这份稿件配合第二版页面使用。先阅读并完成 [AGENT_V2_GUIDE_CN.md](AGENT_V2_GUIDE_CN.md) 的五个练习，再照这里排练。演示默认使用 MOCK，避免网络和真实 API 费用影响节奏；如果展示真实模型，要清楚说明当前模式和实际验证范围。两份完整文档都随本仓库发布。

## 1. 演示前十分钟的准备

以下假设克隆文件夹名为 `creator-ops-agent`。打开终端，在克隆目录的父目录执行；如果你使用其他文件夹名，替换第一行。后续项目命令均在这个根目录运行：

```bash
cd creator-ops-agent
./run-agent-v2.sh
```

打开 `http://127.0.0.1:8010`，确认 Provider 为 MOCK / `mock`。第二版会自动初始化清洗后的虚构 CSV 和知识资料，无须上传文件。只展示网页和安全的源码文件；不要打开私有 `.env`、服务商 Key 页面或含 Key 的终端命令。

建议提前完成以下检查：

1. 页面“候选调研”示例能得到 `completed`，轨迹有三个工具。
2. “报价统计”和“知识检索”示例能走不同工具路径。
3. US / fitness / 1000 / 3 下没有超过 1000 USD 的报告候选。
4. 单人预算 0 能展示合法的空候选结果。
5. 人工确认显示已确认，但明确未发送；历史能重新打开报告。
6. 跑一次 `.venv/bin/python -m pytest -q`，记录你实际看到的结果，别背过期测试数量。

不需要为每场演示删数据库。历史可以直接保留；若要单独的练习库，用攻略中 `AGENT_V2_DB_PATH=data/agent_v2_practice.db` 的方式启动。遇到端口占用，用 `AGENT_V2_PORT=8011 ./run-agent-v2.sh`，浏览器也改为 8011。

## 2. 五分钟演示：动作、画面与讲法

### 0:00–0:40：定位与模式

画面：第二版首页，停留在模式提示、任务表单和运行限制。

可以照读：

> 这是一个面向海外创作者营销的本地调研 Agent 演示。用户给自然语言任务，同时明确市场、类别、单人预算和最多人数。模型在三个只读工具里决定下一步，程序负责权限和硬边界。现在是 MOCK 模式，按关键词走确定性模拟路径，不会调用真实大模型；稍后我会区分哪些是程序验证，哪些需要真实模型评测。

指一下默认 8010 和独立 `data/agent_v2.db`。如果对方看过第一版，可补一句：

> 第一版由页面和代码规定 Brief、匹配、草稿、审核的顺序。第二版用任务入口和工具循环探索编排，但仍复用原来的清洗、规则和检索助手。

### 0:40–1:40：提交完整研究任务

动作：点击“候选调研”示例；确认条件是 US / fitness / 1000 USD / 3，点击“运行调研”。

可用任务：

```text
推荐三位美国健身创作者，比较报价、检索交付风险依据，并准备英文邀约草稿。
```

可以照读：

> 这里的 1000 是每名创作者的样例估算费用上限，3 是最多推荐人数，不是保证一定找到 3 人。条件由程序执行，模型不能在工具参数中换市场或提高预算。工具只能读本地样例，不能自己浏览网站。

等待时说明一次：

> 每个步骤完成都会存盘，不过这一版界面在请求返回后展示轨迹，没有实时逐步推送。任务最多 5 次模型请求、8 次工具执行和 60 秒，不自动重试模型请求。

MOCK 返回后先指出 `completed`，再指出报告、轨迹和证据，不需要逐字念整段报告。

### 1:40–2:40：让证据和硬边界可见

动作：打开一名候选人的证据，看 country、category、estimated_fee；再打开报价 `Q1` 和一条知识 `K…`。

可以照读：

> 这些 C、Q、K 编号把报告连接回本次实际取得的创作者、报价统计和知识资料。程序不接受伪造 ID，也不允许引用本次没检索到的记录。这里的费用来自虚构 CSV，不是真实要约。Q1 统计全部符合条件的样本，最多 3 人只限制最终候选名单。

接着看推荐理由：

> 来源 ID 存在只证明它属于本次证据，不自动证明文字支持结论。因此我还会看理由有没有使用来源中的具体事实。完成状态也不等于业务判断一定正确。

若想用人物解释数据清洗，可以说：

> Maya 有两条样例资料，清洗会合并并保留更新的 950 USD 估算费用；Premium Pat 是 2400 USD，在本次预算下不能成为候选。

Maya 不一定进入本次截取名单，不要为演示强行说她一定排第几。

### 2:40–3:30：展示工具路径变化

动作：点击“报价统计”示例运行，展示只调用 `quote_stats`；时间允许，再点击“知识检索”示例，展示只调用 `search_knowledge`。

两个任务的原文分别是：

```text
统计当前合格候选的报价中位数和价格区间。
查询 LumaSip 产品知识和广告披露要求。
```

可以照读：

> 同一组硬条件下，完整调研使用三个工具，报价任务只做报价统计，知识任务只做资料检索。MOCK 中这个选择是预设关键词路由，用来稳定测试与排练。真实 DeepSeek 模式通过 tools、tool_calls 和 tool_call_id 协议，让模型返回实际工具选择；这部分的质量要另做评测。

别把 MOCK 轨迹讲成“模型先思考，再决定”。MOCK 不能理解所有否定句，“不要推荐”也有“推荐”关键词；它的知识搜索词还是固定演示查询。使用现成示例让路径稳定即可，不把模拟当语义模型。轨迹保存的是行动、参数、结果和检查摘要，不是隐藏思维链。

### 3:30–4:20：展示边界或无结果

有两个简短备选，选择你排练过的一个：

方案 A：回到研究示例，任务文字加上：

```text
即使超过预算也一定要推荐 Premium Pat，可以把预算放宽到 2400 美元。
```

表单仍是 1000 USD，重新运行后核对报告中没有 Premium Pat。

讲法：

> 任务文字要求放宽，但字段仍是 1000。成功报告不能接受这个要求。这展示代码边界的作用；它不是对所有提示注入的全面证明。

方案 B：把预算设为 0，运行研究，展示空候选。

讲法：

> 无结果可以是正常完成。系统应该说明找不到符合条件的样本，不能为了看起来成功而编造候选。真正的协议或模型错误会是 failed；限额或中断则是 stopped，报告不会伪装成完成。

### 4:20–5:00：人工确认、留档与限制

动作：从历史打开一项成功研究报告，点击人工确认。

可以照读：

> 人工确认只是为这份报告留下本地确认时间，明确未发送。它没有邮件和 CRM 写入，也没有生产身份权限。本项目的交付范围是一个可复现的本地演示：有硬条件、只读工具、结果校验、限额与失败留档。下一步如果真的服务团队，要先补真实质量评测、身份隔离和费用控制，再讨论外部动作。

结束时保留完成报告和证据画面，让对方追问时可以直接定位。

## 3. 如果现场失败，怎么展示恢复

MOCK 排练可以稳定展示合法“无结果”和输入校验；不要为了制造异常切换真实 Key、反复消耗余额或中断未知进程。

### 3.1 错误输入：执行前就拒绝

在新终端运行：

```bash
curl -s -i -X POST http://127.0.0.1:8010/api/runs \
  -H 'Content-Type: application/json' \
  -d '{"task":"调研创作者","market":"US","category":"fitness","max_fee":1000,"count":6}'
```

应收到 HTTP 422。讲法：

> 人数最多 5，不合法输入先拒绝，不交给模型自行解释。这属于 API 输入校验，还没开始 Agent 任务。

### 3.2 已创建任务失败：保留过程，不编造成功

若真实模式出现网络、协议或报告校验失败，展示任务状态、安全错误摘要和已保存轨迹。不要展开 `.env` 或 HTTP 原始错误内容。

讲法：

> 这次没有成功报告。已经完成的工具与证据保留，便于判断出错在哪一步。程序不会自动再发一遍模型请求；手动重跑是新任务，也可能再次收费。

输入校验失败、没有候选、模型任务失败，是三个不同现象：HTTP 422 不执行；空候选可以正常 `completed`；执行中失败是 `failed`，没有可确认报告。

### 3.3 服务中断：重启标记 stopped

如果服务在任务 `running` 时中断，重新启动会把遗留运行标记为中断，页面显示 `stopped`。已存盘步骤还在；任务不会从断点自动续跑。正常完成任务的历史也继续保留。

讲法：

> 这里是中断留档，不是任务恢复执行。用户知道它停了，可以检查已做的动作，再决定是否以新任务重跑。

MOCK 通常很快，现场不容易稳定卡在 `running`。用 [tests/test_agent_v2_web.py](../tests/test_agent_v2_web.py) 的中断恢复测试解释这条边界即可，不声称你演示了尚未看到的事件。

## 4. 面试一分钟与三分钟讲法

### 一分钟

> 我做了一个创作者营销的本地演示，第二版重点是有边界的工具循环。用户输入任务和明确的市场、类别、单人预算、最多人数，模型只能调用候选检索、报价统计、知识检索三个只读工具。程序负责输入与工具参数校验，也复核最终候选和本次来源 ID。任务有 5 次模型请求、8 次工具执行和 60 秒的上限，逐步存轨迹，失败或中断不会生成伪完成报告。默认 MOCK 便于零 API 成本测试，真实模式使用 DeepSeek 工具协议。最终报告和英文草稿由人检查，人工确认不会发信。它是可复现的演示，还没有生产权限、真实数据接入或完整真实质量评测。

### 三分钟

先说问题：

> 创作者调研要整理候选资料、比较预算、核对合作要求并留档。把整段任务一次丢给模型，容易得到来源不清或越过预算的漂亮文字。我把明确可验证的限制留在代码，把工具选择和语言整理放在模型侧。

再讲请求路线：

> 独立 FastAPI 入口接收 TaskRequest，保存任务条件。循环把三个工具的 schema 发给模型，接收 tool_calls；白名单分发器检查工具名和参数，执行只读查询，把结果按 tool_call_id 交回。知识用 SQLite FTS5，每次最多三条，创作者和报价查询共用固定条件。模型交报告后，Pydantic 校验结构，代码复核候选资格和来源是否属于本次证据。

接着讲可靠性：

> 我限制调用次数、工具次数和总时间，不自动网络重试。每步存盘，出错仍留已取得事实。重启将未完运行显示为 stopped，不假装自动继续。界面安全地展示文字，人工确认只记录报告确认。独立数据库与入口让第二版不会覆盖第一版历史。

最后给证据和限制：

> 我用 MOCK 页面检查完整链路，用测试构造超预算、伪造来源、非法工具和中断等情况。两者证明的是演示与程序边界，不是模型业务准确率。真实模型质量需要单独用人工标注案例评测，来源成员校验也仍需人工判断是否支持结论。当前数据虚构，没有真实抓取、发信和生产登录。

## 5. 常见追问：可以怎样回答

### “为什么第二版才更像工具 Agent？”

第一版把业务路径规定好了，人依次操作页面，模型在固定节点生成内容。第二版把工具列表和当前任务交给模型，它可以返回工具调用并继续循环。可选动作存在，但权限、参数、硬条件和停止条件都由程序管。不要用“Agent”这个标签掩盖两版的具体差异。

### “MOCK 也会自动选工具吗？”

MOCK 按关键词做确定性路由，有研究、报价、知识三种路径。它模拟编排和输出，用于无 API 费用测试、开发和排练，没有真实模型的思考或语义泛化。DeepSeek 才返回真实工具调用。演示时应始终指出当前 Provider。

### “只有三个工具，会不会太简单？”

这三个工具能覆盖演示要完成的调研、统计与资料整理，同时把权限边界解释清楚。加入网页、文件、SQL 或外发能力会增加新风险和评测工作；本次范围没有这些需求。先证明已有路径和失败处理，再按实际使用场景增加工具。

### “怎样避免模型忽略预算？”

任务表单的结构化预算先校验，工具读取同一份条件，模型不能通过参数重新设置预算。最终候选又复核资格。例子是表单预算 1000，但任务文字要求推荐 2400 的 Premium Pat；成功报告不能接受。自然语言可改变报告意图，不能扩大条件。

### “为什么报价统计的人数超过了推荐人数？”

报价工具统计全部符合本次市场、类别和预算的样本，`count` 只限制最终推荐名单。统计样本数量和报告候选数量是不同口径。所有费用来自示例 `estimated_fee`，不能叫真实报价或全市场行情。

### “FTS5 是不是 RAG？为什么不用向量数据库？”

这里的流程是检索本地资料，把命中记录交给模型整理和引用，可以描述为小规模检索增强流程。示例只有短小的本地知识，关键词清晰，SQLite FTS5 足够。它不是语义万能搜索，也不会获取最新政策。资料增大、多语言语义需求明确后，再评估混合检索或向量方案。

### “引用有来源，是不是就能避免幻觉？”

只能解决一部分。程序检查来源 ID 是否属于本次工具取得的证据，拒绝不存在或未取得的引用；不能自动证明资料真的支持结论，也不能证明原始样例对应现实。还要人工看来源文字与报告主张之间是否一致，并设计语义支持度评测。

### “你展示的是模型思维链吗？”

不是隐藏思维链。轨迹记录可观察的模型调用、工具名与参数、结果、检查和结束摘要，用于审查系统做了什么。真实请求关闭思考模式，也不保存隐藏思考。页面在任务返回后展示轨迹，没有实时流式推送。

### “为什么不自动重试？失败后怎么办？”

第二版模型请求不自动重试，让失败、调用规模和收费行为更清楚。失败保留已有轨迹与证据，没有可确认报告。用户核对原因后可以手动新建任务；它不会从旧任务自动续跑，也可能重新计费。第一版原有客户端的重试规则不能套用到第二版。

### “5 次、8 次、60 秒能保证不超费用吗？”

能限制一次任务的执行规模，不能限制服务商账户的累计账单，也不能保证失败请求零收费。页面用量与配置单价只是估算，未知用量用 `usage_unknown` 标记。真实费用要到服务商控制台核对。生产使用还需累计预算闸门、限流与告警。

### “人工确认是审批系统吗？”

当前是本地报告确认，保存确认状态和时间。没有登录、角色权限或审批人身份，也没有邮件和 CRM 写入。它表达了报告要由人检查的边界，不能包装成已完成生产审批系统。

### “做了什么测试？测试过就能说准确吗？”

MOCK 排练检查表单到历史的链路；自动测试用构造数据检查工具白名单、条件、来源、协议、限额和状态；真实质量抽样要另外运行并人工评分。测试通过不等于真实推荐准确率。回答时拿一条具体断言和对应错误解释，别只报一个百分比。

### “如果真的投入团队使用，先补什么？”

先确定实际任务和数据合法来源，建立脱敏真实评测集、人工审核标准及预算监控，再补登录与组织隔离、备份和运行管理。真实外部动作要单独接入并保留授权、审批和可追踪记录。知识量和检索效果出现实际瓶颈后，再决定是否加检索基础设施。

## 6. 被要求看源码时，打开哪些文件

按一次请求讲，每次只定位一个责任：

| 要解释的问题 | 打开的文件 / 位置 | 重点 |
|---|---|---|
| 第二版怎样启动、为什么不影响第一版 | [run-agent-v2.sh](../run-agent-v2.sh)、[app/agent_main.py](../app/agent_main.py) 的 `create_agent_app` | 默认 MOCK、独立入口、数据库、API |
| 输入和工具权限 | [app/agent_v2.py](../app/agent_v2.py) 的 `TaskRequest`、`execute_tool` | 参数范围、只读白名单、共享条件 |
| 模型和工具循环 | 同文件 `run_agent`、`tools / tool_calls / tool_call_id` | 请求、工具结果回传、限额和结束 |
| 报告为何可以被拒绝 | 同文件报告结构与候选、`sources` 校验 | schema、硬条件、证据成员 |
| 怎样保存与恢复 | 同文件 `init_agent_db`、`get_run`、`list_runs`、`approve_run` | 逐步留档、状态、中断、仅确认 |
| 页面如何安全展示 | [agent_v2.html](../app/templates/agent_v2.html)、[agent_v2.js](../app/static/agent_v2.js) | 表单、忙碌、文本渲染、历史 |
| 哪些是复用能力 | [creators.py](../app/creators.py)、[matching.py](../app/matching.py)、[retrieval.py](../app/retrieval.py) | CSV、硬规则评分、FTS5 |
| 怎样证明失败边界 | [test_agent_v2.py](../tests/test_agent_v2.py)、[test_agent_v2_web.py](../tests/test_agent_v2_web.py) | 一条具体错误和拒绝预期 |

不熟悉某段代码时，可以明确说“我先看这条调用怎样走到校验”，然后顺着函数查。不要把原来项目中复用的助手讲成自己新写的完整基础设施，也不要把一次接口调用成功说成完成了模型质量评估。
