# Creator Research Agent V2｜创作者调研 Agent

面向海外创作者合作场景的本地工具调用演示。用户提交调研任务和结构化条件，模型在三个只读工具内选择动作，程序校验调用与结果，最终呈现候选报告、英文邀约草稿、本次证据和执行轨迹。

项目使用 FastAPI、SQLite/FTS5、Pydantic、HTTPX 和原生 HTML/CSS/JS。所有创作者、品牌、联系方式与业务资料都是虚构样例。默认 MOCK 不需要 API Key；真实模式接入 DeepSeek 工具调用协议。第二版尚未进行真实 DeepSeek 付费实测，已有协议测试使用受控 HTTP 响应，不能据此声称真实模型效果已验证。

## 运行与第一次演示

需要 Python 3.11+。macOS、Linux 与 Windows 的依赖安装和手动启动命令见 [首页：快速启动](README.md#快速启动)，选择 **V2** 入口 `app.agent_main:app`。macOS/Linux 也可以在项目根目录使用 Bash 脚本：

```bash
bash ./run-agent-v2.sh
```

脚本默认强制 MOCK，不读取私有 `.env`。首次安装依赖可能联网；MOCK 调研任务不调用模型 API。浏览器打开 [http://127.0.0.1:8010](http://127.0.0.1:8010)，确认页面显示 MOCK：

1. 点击“候选调研”，保留 US / fitness / 1000 USD / 最多 3 人。
2. 点击“运行调研”，检查报告候选是否满足条件。
3. 展开一个创作者来源、报价来源和知识来源，核对报告与证据。
4. 查看执行轨迹，再点击人工确认，从历史重新打开同一报告。
5. 分别运行“报价统计”和“知识检索”示例，观察不同工具路径。

默认数据库为 `data/agent_v2.db`，首次启动自动初始化清洗后的示例 CSV 和知识资料，无须到 V1 页面导入。停止服务用 `Ctrl+C`；再次启动保留历史。需要独立练习时可指定一个未使用的 `AGENT_V2_DB_PATH`，原数据继续保留。

## 三个只读工具

任务包含自然语言说明，以及市场、类别、单人 USD 预算、最多候选人数。市场限定 US/UK/CA，类别限定 fitness/tech/lifestyle/all，预算为 0–10000 的有限数值，候选人数为 1–5。

| 工具 | 参数 | 返回内容与边界 |
|---|---|---|
| `search_creators` | `{}` | 按本次条件查询本地虚构创作者，并复用平台、粉丝范围等硬规则；返回规则排序前 10 条与合格总数。 |
| `quote_stats` | `{}` | 统计全部合格样本的费用数量、最小值、中位数与最大值；最终推荐人数不改变统计口径。 |
| `search_knowledge` | `{"query": "..."}` | 用 SQLite FTS5 检索本地产品、披露与交付资料，每次最多 3 条；查询最多 300 字符。 |

前两个工具读取已校验的条件，不接受模型重新指定市场或提高预算。费用来自 CSV 的样例 `estimated_fee`，需要人工重新核实，不能当作真实签约报价或市场行情。

## 工具循环与程序边界

一次任务沿着以下流程执行：

```text
任务 + 结构化条件
  → 模型返回工具调用
  → 白名单与参数校验
  → 查询本地资料，保存证据和轨迹
  → 按 tool_call_id 将结果交回模型
  → 继续调用或提交 JSON 报告
  → 校验报告结构、候选资格和本次来源 ID
  → 展示报告，等待人工检查与确认
```

- 每任务最多 5 次模型请求、8 次工具执行和 60 秒执行期限；模型请求不自动重试。
- 工具只执行固定查询助手；未知工具、非法参数、重复调用与越界结果会受到检查。
- Pydantic 校验报告字段与范围；候选人数、身份、预算资格和引用再次由程序核对。
- 报告通过 `C…`、`Q1`、`K…` 来源 ID 连接到本次取得的证据，拒绝不存在或本次未取得的来源。
- 每步保存状态、轨迹与证据。失败为 `failed`，达到限制或中断为 `stopped`；失败或停止不会保存可确认的成功报告。合法的无候选结果可以正常完成。
- 服务重启将遗留 `running` 标为 `stopped`，保留已存记录；重新提交创建新任务，不从断点续跑。
- 一个本地进程同时执行一项任务。页面在请求返回后展示轨迹，没有实时流式推送。

来源成员校验只证明 ID 属于本次证据集合，不能证明资料支持报告每句话。轨迹记录可观察的动作、参数与结果，不是隐藏思维链。

## 人工确认与两版关系

只有 `completed` 且具备完整报告的任务可以人工确认。确认保存本地状态和时间，界面明确显示“未发送”；英文草稿仍需要人检查。

V1 的主要步骤由页面和程序规定，涵盖 Brief、CSV 导入、匹配、外联草稿、审批与文字审核。V2 将入口改为任务和工具循环，复用清洗、硬规则、SQLite 与知识检索。两版共享源码基础，拥有各自入口、页面和默认数据库；V2 不覆盖 V1 全部业务页面。V2 的真实模型工具协议由 `app/agent_v2.py` 实现。

## 可选 DeepSeek 与当前限制

按照 [学习攻略第 7 节](docs/AGENT_V2_GUIDE_CN.md#7-可选你自己运行一次真实-deepseek) 准备私有配置。macOS/Linux 明确切换真实模式时运行：

```bash
bash ./run-agent-v2.sh --deepseek
```

真实请求可能计费。模型和价格以服务商当前配置及账单为准；页面 Token 和成本是已知响应用量下的估算，`usage_unknown` 不能当作零费用。单任务限额不控制账户累计花费；手动重跑可能再次收费。

当前交付范围是本地学习与求职演示：

- 数据与知识为本地虚构样例，没有真实社媒采集、最新行情、外部网页或视频核验。
- MOCK 按关键词走预设路径，知识查询词固定；它不具备真实模型的语义理解能力。
- 没有邮件发送、CRM 写入、生产登录、组织权限或团队任务队列。
- 没有累计总费用闸门或自动语义证据核验；报告、风险与草稿均需人工判断。
- 第二版未进行真实 DeepSeek 付费实测，也没有真实业务准确率或生产稳定性的验证结论。

服务仅绑定本机地址使用。发布源码应排除私有配置、API Key、运行数据库、任务历史、虚拟环境和缓存；后续自行输入的任务或资料也不应自动作为公开展示素材。
